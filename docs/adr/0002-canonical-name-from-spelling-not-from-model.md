# Каноническое имя получается из написания, а не от модели

Модель возвращает написание сущности как в тексте (и полную форму, если аббревиатура раскрыта в самой аннотации). Каноническое имя получается дальше в два шага без модели: детерминированная нормальная форма (регистр, дефисы и пробелы, число), затем словарь синонимов «нормальная форма → каноническое имя». Запись словаря вступает в силу только после утверждения разработчиком; словарь хранится файлом в репозитории.

Исходный замысел разработчика был другим: модель сама выдаёт каноническое имя, словарь синонимов ведётся для ста самых частых сущностей. Замена принята разработчиком в сессии проектирования 10 ноября 2026 по рекомендации агента. Доводы ниже — наблюдения агента.

## Почему не имя от модели

Через Batch API каждая аннотация обрабатывается отдельно, и модель не видит, как назвала ту же сущность в соседней: «RAG», «Retrieval-Augmented Generation» и «retrieval augmented generation (RAG)» становятся тремя сущностями. Словарь на сто самых частых склеивает только уже популярное, а новая сущность, рассыпанная на три написания по десять упоминаний, не проходит порог и не попадает в растущие. Ошибка систематическая и приходится на то, ради чего сервис существует.

## Рассмотренные варианты

- **Автоматическая склейка без утверждения (моделью или по эмбеддингам).** Отклонено: ложная склейка (GPT-4 и GPT-4o, LoRA и QLoRA) даёт правдоподобный, но неверный тренд и ничем себя не выдаёт. Часть таких случаев — решение о предметной области, а не ошибка.
- **Jev (TypeSafe AI) для оценки пар-кандидатов.** Вне плана: утверждение словаря занимает мало времени, а автоматическое утверждение по порогу отменяет правило выше.

## Следствия

- Сохранённое написание позволяет пересчитать нормализацию без нового прогона извлечения и без денег; ошибки в нормальной форме и пополнение словаря не требуют полного прогона.
- Кандидатов в словарь подбирают: пары «полная форма — аббревиатура» из аннотаций, ближайшие соседи по эмбеддингам имён сущностей (разовый локальный скрипт, без векторного хранилища), оценка пар моделью. Аббревиатура с двумя разными расшифровками в корпусе выносится разработчику как конфликт.
- Метрика извлечения зависит от состояния словаря, поэтому версия словаря записывается в журнал замеров.
- Словарь требует регулярного утверждения: без него новые сущности остаются рассыпанными по написаниям и ниже порога, а сервис продолжает отвечать без видимой ошибки.
