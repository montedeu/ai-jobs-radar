# Агент читает данные только через MCP-сервер и проверяет ссылки кодом

Агент на LangGraph — граф из четырёх шагов: сбор данных вызовами инструментов MCP-сервера (с пределом шагов), ответ с идентификаторами статей у каждого утверждения, проверка ссылок обычным кодом, одно исправление по списку нарушений. Собственных запросов к базе у агента нет. Ни MCP-сервер, ни агент не обращаются к arXiv при ответе на вопрос (условие разработчика).

Требование «каждое утверждение со ссылкой» поставил разработчик. Устройство графа принято им в сессии проектирования 10 ноября 2026 по рекомендации агента; доводы ниже — наблюдения агента.

## Что проверяет код

- каждый идентификатор arXiv в ответе встречается в ответах инструментов этого же запроса;
- у каждого утверждения есть хотя бы одна ссылка;
- названы дата расчёта и сравниваемые периоды.

Если ответ не прошёл проверку и после исправления, пользователь получает его с явной пометкой неподтверждённых утверждений.

## Почему так

- Claude Desktop с теми же инструментами уже отвечает на те же вопросы; без детерминированного шага агент был бы вторым интерфейсом к тому же самому. Проверка ссылок — то, что он гарантирует, а Claude Desktop нет.
- Доступ только через MCP-сервер держит определения трендов в одном месте и даёт серверу второго потребителя.
- Инструмента с произвольным SQL нет: иначе определение «растёт» задавала бы модель, и на один вопрос оно получалось бы разным.

## Рассмотренные варианты

- **Модель-судья для проверки пересказа.** Отклонено: деньги, время и ещё одна вещь, которую саму надо проверять.

## Следствия

- Проверка ловит выдуманную ссылку, но не неверный пересказ настоящей статьи.
- Набор из 15 вопросов с ожидаемыми фактами проверяет агента (выбор инструмента, параметры, отсутствие искажений), а не правильность трендов: ожидаемые факты получены прямыми вызовами тех же инструментов на закреплённые дату расчёта, прогон извлечения и версию словаря.
- MCP-сервер и агент доступны только с токеном в заголовке; у агента пределы шагов, токенов и частоты запросов.
