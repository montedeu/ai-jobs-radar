# Рост считается по скользящим окнам и только внутри одного прогона извлечения

Рост определяется сравнением двух соседних окон равной длины, заканчивающихся на дату расчёта: по умолчанию 90 дней против предыдущих 90, конец — вчерашний день. Доля — статьи среза с упоминанием сущности, делённые на статьи среза, прошедшие извлечение, за то же окно. Растущая сущность: не меньше 20 упоминаний в последнем окне и доля выше, чем в предыдущем. Новая: не меньше 20 в последнем и меньше 5 в предыдущем, показывается отдельно и без отношения долей (запрос его считает; инструмент `rising_entities`, когда появится, не будет его показывать). Затухающая: зеркально, с порогом на предыдущем окне. Оба числа упоминаний всегда показываются рядом с отношением.

Все упоминания в расчёте принадлежат одному прогону извлечения. Полный прогон запускается только вручную и покрывает историю, собранную к моменту его запуска. Статьи, собранные после этого, ежедневная задача отправляет в текущий прогон; в новый прогон они попадают после переключения на него. Пока полный прогон не завершён, сервис отвечает по предыдущему.

## Чьи это решения

- Исходное определение разработчика: доля по календарным месяцам, последние три месяца против предыдущих трёх, минимум 20 упоминаний, дата — первая версия статьи.
- Агент предложил окна из полных календарных месяцев. Разработчик возразил в сессии: «тогда не лишится ли это пользы анализа новых статей, если всё будет запаздывать на месяц?» Скользящие окна по дням приняты в ответ на это возражение.
- Остальное принято разработчиком в сессии проектирования 10 ноября 2026 по рекомендациям агента; доводы ниже — наблюдения агента.

## Почему так

- **Знаменатель только по обработанным статьям.** Свежие статьи, по которым пакет извлечения ещё не вернулся, не могут дать упоминаний; в знаменателе они занижали бы долю последнего окна у всех сущностей сразу.
- **Порог на «своём» окне.** Порог на сумму двух окон пропускал бы в растущие сущность с 19 и 1 упоминанием.
- **Новые отдельно.** При почти пустом предыдущем окне отношение долей ничего не значит и ломает сортировку.
- **Один прогон.** Если соседние окна извлечены разными промптами, разница между ними — разница промптов, а не изменение в области. По той же причине нельзя экономить, прогоняя новым промптом только последние месяцы.

## Следствия

- Ответ меняется каждый день, поэтому у запроса и у инструмента есть параметр даты расчёта; тесты и набор вопросов для агента используют закреплённую дату.
- Помесячный ряд существует отдельно как история сущности и не служит основанием для вывода о росте.
- Два окна должны помещаться в обработанную историю, поэтому самое длинное окно — её половина: около 187 дней на 10 ноября 2026 и больше с каждым днём. «За последний год» трактуется как 182 дня против 182, с названными периодами. На окно длиннее обработанной истории инструмент отвечает отказом с объяснением, а не цифрой по обрезанному окну.
- Статистической значимости в определении нет: отношение 1,1 при 25 и 23 упоминаниях попадёт в список.
- Свежий край немного недосчитан: дополнительная категория может появиться у статьи через несколько дней после подачи.
