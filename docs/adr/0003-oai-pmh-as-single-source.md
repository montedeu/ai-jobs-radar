# Один источник статей — OAI-PMH, и для истории, и для ежедневного сбора

Первая выгрузка среза идёт через OAI-PMH по набору категории без параметра `from`; статьи с датой раньше начала истории отбрасываются на нашей стороне. Дальше та же задача ходит ежедневно с отметки последнего успешного сбора, с перекрытием в один день. Статья определяется идентификатором arXiv без номера версии; повторный приход обновляет запись.

Исходный замысел разработчика был другим: история из снимка Kaggle один раз, дальше OAI-PMH. Замена принята разработчиком в сессии проектирования 10 ноября 2026 по рекомендации агента. Доводы ниже — наблюдения агента.

## Почему не снимок Kaggle

Два источника — это два разбора (JSON и XML) к одной схеме, причём разбор Kaggle нужен один раз в жизни, и шов между датой снимка и первым ежедневным сбором, где неделя статей может потеряться незаметно. При одном источнике первый запуск проверяет тот же код, который потом работает каждый день.

Kaggle остаётся запасным вариантом, если замер первого запуска покажет, что полная выгрузка неприемлемо долгая или arXiv её ограничивает.

## Следствия

- Первая выгрузка долгая: набор отдаётся постранично за всю историю arXiv, а нужна из него часть. Для наборов cs.LG и cs.CV это часы.
- OAI-PMH отбирает по дате изменения, поэтому статья возвращается при каждой правке. Хранится последняя аннотация; дата статьи — всегда дата первой версии; извлечение повторяется только при изменении текста аннотации (сравнение хеша), иначе массовое обновление метаданных на стороне arXiv потратило бы бюджет извлечения.
- Переписанная аннотация может изменить долю за прошлые месяцы на несколько статей задним числом.
- История начинается 1 ноября 2025 и растёт; старое не удаляется. Разработчик отказался от глубины в 24 месяца как от избыточной.
- Срез категории — все статьи, у которых она есть среди категорий, основной или дополнительной. Срезы пересекаются, итог по нескольким считается по различным статьям.
