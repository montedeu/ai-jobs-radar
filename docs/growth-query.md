# Запрос роста: условие

Учебный островок: запрос пишет разработчик. Файл — `src/research_radar/sql/growth.sql`, один оператор `SELECT`. Определения — в `GLOSSARY.md` (окно, доля, растущая, новая и затухающая сущность) и в ADR 0004.

Проверка: `uv run pytest tests/test_growth.py`. Пока файла нет, тесты пропускаются.

## Что есть в базе

| Отношение | Что в нём | Нужные столбцы |
|---|---|---|
| `paper` | статьи | `arxiv_id`, `first_version_date` (дата статьи) |
| `paper_category` | срезы: по строке на каждую категорию статьи, основную и дополнительные | `arxiv_id`, `category` |
| `paper_extraction` | статьи, по которым прогон извлечения завершён, нашёл он что-то или нет | `run_id`, `arxiv_id` |
| `paper_entity` | упоминания под каноническими именами: не больше строки на статью, тип и сущность | `run_id`, `arxiv_id`, `entity_type`, `canonical_name` |

Сущность — это пара (`entity_type`, `canonical_name`): одно и то же имя с разными типами — две сущности.

## Параметры

Подставляются по имени, в синтаксисе psycopg: `%(as_of)s`.

| Параметр | Тип | Смысл |
|---|---|---|
| `run_id` | bigint | прогон извлечения; всё считается только внутри него |
| `category` | text | срез |
| `as_of` | date | дата расчёта |
| `window_days` | integer | длина окна в днях |
| `min_mentions` | integer | порог упоминаний |
| `new_max_previous` | integer | граница «почти нет упоминаний» для новой сущности |

Знак процента внутри запроса psycopg принимает за начало параметра; буквальный процент пишется как `%%`.

## Окна

Последнее окно — `window_days` дней, заканчивающихся датой расчёта включительно. Предыдущее — `window_days` дней сразу перед ним. При `as_of` = 31 октября и окне в 10 дней это 22–31 октября и 12–21 октября.

## Что вернуть

По строке на сущность, которая оказалась растущей, новой или затухающей. Остальные сущности не возвращаются.

| Столбец | Смысл |
|---|---|
| `canonical_name`, `entity_type` | сущность |
| `kind` | `rising`, `new` или `fading` |
| `mentions_last`, `mentions_previous` | число статей среза с упоминанием сущности в каждом окне |
| `papers_last`, `papers_previous` | число статей среза, прошедших извлечение в этом прогоне, в каждом окне |
| `share_last`, `share_previous` | доля в каждом окне: упоминания, делённые на статьи того же окна |
| `ratio` | `share_last / share_previous`; `NULL`, если в предыдущем окне упоминаний нет. Считается для всех видов, включая `new`: запрос возвращает число, а не показывать его у новой сущности — дело будущего инструмента (ADR 0004) |

Статья считается, если она входит в срез, прошла извлечение в прогоне `run_id` и её дата попадает в окно. Статья с несколькими категориями — одна статья.

## Виды

- **`new`**: `mentions_last` ≥ `min_mentions` и `mentions_previous` < `new_max_previous`.
- **`rising`**: `mentions_last` ≥ `min_mentions`, сущность не новая, и `share_last` > `share_previous`.
- **`fading`**: `mentions_previous` ≥ `min_mentions` и `share_last` < `share_previous`.

Пороги сравниваются включительно. Равные доли — ни рост, ни затухание.

## Порядок строк

Сначала все `rising`, затем `new`, затем `fading`. Внутри:

- `rising` — по убыванию `ratio`;
- `new` — по убыванию `mentions_last`;
- `fading` — по возрастанию `ratio` (сильнее всего упавшие первыми).

При равенстве — по `canonical_name`, затем по `entity_type`.

## Что гарантирует вызывающий код

- В обоих окнах есть хотя бы одна статья среза, прошедшая извлечение: если обработанной истории не хватает на два окна, запрос не вызывается.
- 1 ≤ `new_max_previous` ≤ `min_mentions`: обёртка отклоняет другие значения до вызова запроса. Поэтому сущность не может быть сразу новой и затухающей, а у растущей сущности в предыдущем окне есть хотя бы одно упоминание и `ratio` определён.
